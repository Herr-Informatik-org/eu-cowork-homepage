An instance is managed with the usual Docker Compose commands. There is no command line of its
own that you would have to learn first.

| Purpose | Command |
|---|---|
| Start | `docker compose up -d` |
| Status | `docker compose ps` |
| Follow the log | `docker compose logs -f` |
| Restart | `docker compose restart` |
| Stop | `docker compose down` |

Not every delivery starts with the same scope. Which additional settings a call needs in your
delivery is described in the operating documentation. They then belong to **every** call.

## Bundled helper scripts

For installation, updating, backup and migration the delivery ships ready made scripts, so that
these procedures do not have to be assembled by hand. Their invocations, options and the right
order are described in the operating documentation included with the delivery. Customers
receive it together with their access.

<Aside type="caution" title="Back up before every update">
Without exception. Besides the database, a backup covers the configuration and the uploaded
files; the bundled backup tool takes both along. An archive contains credentials and is stored
protected accordingly.
</Aside>
