All settings of an instance live in a single file: `distribution/.env`. This page lists every
variable from the shipped template `distribution/.env.example`, grouped by topic. It is
written for everyone who sets up or operates an instance.

The installer creates the `.env` from the template on the first run, generates the secrets and
sets the permissions to `600`. The file never belongs in a repository and never in a ticket.

<Aside type="danger" title="No real values in this documentation">
This page contains only the placeholders from the template. A value like
`__SET_YOUR_EUROUTER_KEY__` is exactly that: a placeholder that you replace with your own key
on your server. Never pass on the contents of your real `.env`.
</Aside>

## What the columns mean

| Column | Meaning |
|---|---|
| **Variable** | the name exactly as it appears in the `.env` |
| **Purpose** | what the value is needed for |
| **Required** | whether the instance runs without this value. Some values are only needed with a particular Compose profile |
| **Default** | the value from `.env.example`. `commented out` means the line starts with `#` and is therefore inactive |

## The three things you really have to touch

The rest of the file is preset so that an instance starts. Three areas you have to set
yourself.

<Aside type="tip" title="Short version">
1. Enter `EUROUTER_API_KEY`, otherwise no model responds.
2. Set `DOMAIN_CLIENT`, `DOMAIN_SERVER` and `EUCOWORK_DOMAIN` to your domain as soon as the
   instance no longer runs only locally.
3. In production behind Caddy, set `API_BIND=127.0.0.1`.
</Aside>

**`EUROUTER_API_KEY`** is the only value a standard customer has to enter themselves. Without
it the stack does start, but every model request fails.

**The three domain variables** are set to `localhost` out of the box. `DOMAIN_CLIENT` is the
URL the browser sees and at the same time the basis for invitation links. `DOMAIN_SERVER` is
the server URL and therefore the basis of the redirect URI for connectors with per-user
sign-in. `EUCOWORK_DOMAIN` is
used by Caddy and by the Office manifest. If they stay on `localhost`, you send invitations
with a link that only works on the server itself.

**`API_BIND`** is set to `0.0.0.0` out of the box, because that is convenient locally. In
production with Caddy the value belongs on `127.0.0.1`. Otherwise LibreChat is additionally
reachable directly over HTTP at `<server-ip>:3080`, bypassing TLS, with passwords in clear
text on the network. The firewall does not help against that: ports published by Docker
bypass the ufw rules. Panel and add-in already bind to `127.0.0.1` out of the box.

## Secrets

These values are generated by `install.sh` on the first run. You do not have to do anything
for them.

| Variable | What for |
|---|---|
| `CREDS_KEY` | encrypts the stored credentials of the users, for example a connector connection |
| `CREDS_IV` | initialization vector for the encryption |
| `JWT_SECRET` | signs the session tokens |
| `JWT_REFRESH_SECRET` | signs the refresh tokens |
| `MEILI_MASTER_KEY` | access to the full text search |
| `POSTGRES_PASSWORD` | access to the vector database of the file search |
| `SEARXNG_SECRET` | access to the own metasearch engine |
| `ADMIN_PANEL_SESSION_SECRET` | sessions of the transitional panel |

These values you have to enter yourself, the installer cannot invent them:
`EUROUTER_API_KEY`, optionally `OPENROUTER_API_KEY`, the SMTP credentials and all connector
keys.

<Aside type="caution" title="When migrating to a new server">
`CREDS_KEY` and `CREDS_IV` have to be taken over from the old `.env`. If they are generated
anew, the stored credentials can no longer be decrypted and all users have to set up their
connector connections again.
</Aside>

## Host and ports

| Variable | Purpose | Required | Default |
|---|---|---|---|
| `HOST` | address on which LibreChat listens inside the container | required | `0.0.0.0` |
| `PORT` | port of the chat application, in the container and on the host | required | `3080` |
| `API_BIND` | host binding of the chat port, in production `127.0.0.1` | optional | `0.0.0.0`, line commented out |
| `UID` | user ID with which the containers write into the bind mounts | required | `1000`, the installer enters the ID of the executing account |
| `GID` | matching group ID | required | `1000`, set as well |
| `ADMIN_SIDECAR_PORT` | host port of the own admin panel | required | `3010` |
| `ADMIN_SIDECAR_BIND` | host binding of the admin panel | optional | `127.0.0.1`, line commented out |
| `OFFICE_ADDIN_PORT` | host port of the Outlook add-in, only on `127.0.0.1` | optional | `3040`, line commented out |
| `ADMIN_PANEL_PORT` | host port of the transitional panel, only with the `interim` profile | optional | `3000` |

| Variable | Purpose | Required | Default |
|---|---|---|---|
| `DOMAIN_CLIENT` | chat URL reachable in the browser, also the basis for invitation links | required in production | `http://localhost:3080` |
| `DOMAIN_SERVER` | server URL, basis of the redirect URI for connectors with per-user sign-in | required in production | `http://localhost:3080` |

| `OFFICE_DEFAULT_AGENT_ID` | agent that is preselected in the Outlook pane | optional | empty, line commented out |
| `OFFICE_ENTRA_CLIENT_ID` | Entra app for capturing the writing style through Microsoft Graph | optional | empty, line commented out |
| `OFFICE_ENTRA_TENANT_ID` | matching tenant | optional | empty, line commented out |

## Authentication and encryption

| Variable | Purpose | Required | Default |
|---|---|---|---|
| `CREDS_KEY` | **secret.** Encrypts the stored credentials of the users | required | `GENERATE`, created by the installer |
| `CREDS_IV` | **secret.** Matching initialization vector | required | `GENERATE`, created by the installer |
| `JWT_SECRET` | **secret.** Signs the session tokens | required | `GENERATE`, created by the installer |
| `JWT_REFRESH_SECRET` | **secret.** Signs the refresh tokens | required | `GENERATE`, created by the installer |
| `ALLOW_EMAIL_LOGIN` | sign-in with email and password | required | `true` |
| `ALLOW_REGISTRATION` | self registration of new accounts | required | `true` |
| `ALLOW_SOCIAL_LOGIN` | sign-in through social providers | required | `false` |
| `ALLOW_UNVERIFIED_EMAIL_LOGIN` | controls whether a verification mail is needed. Without configured mail delivery the value has to stay `true`, otherwise every registration fails | optional | `true`, line commented out |
| `BAN_VIOLATIONS` | enables the check for blocks at sign-in | do not change, see below | `true` |
| `NON_BROWSER_VIOLATION_SCORE` | defuses the heuristic "no browser user agent", which would otherwise block sidecar access immediately | required | `0` |

If you leave self registration open, you should enter the allowed email domains in the admin
panel under **Konfiguration → Funktionen → Erlaubte E-Mail-Domains** (configuration, features,
allowed email domains). Otherwise any address can create an account.

## Email

Mail delivery is optional and fully commented out in the template. One set of credentials
drives two paths: the verification and password reset of LibreChat, and the automatic sending
of the invitations from the admin panel. Without these values there is no mail delivery, and
an invitation then only produces a link to copy.

| Variable | Purpose | Required | Default |
|---|---|---|---|
| `EMAIL_SERVICE` | a named service instead of host and port, then the next two lines are not needed | optional | empty, line commented out |
| `EMAIL_HOST` | SMTP server | optional | `mail-eu.smtp2go.com`, line commented out |
| `EMAIL_PORT` | SMTP port. `2525`, `587` and `8025` speak STARTTLS, `465` and `8465` speak TLS | optional | `2525`, line commented out |
| `EMAIL_ENCRYPTION` | `starttls` or `tls`, matching the port | optional | `starttls`, line commented out |
| `EMAIL_USERNAME` | **secret.** SMTP user | optional | `__SET_SMTP2GO_SMTP_USER__`, line commented out |
| `EMAIL_PASSWORD` | **secret.** SMTP password | optional | `__SET_SMTP2GO_SMTP_PASSWORD__`, line commented out |
| `EMAIL_FROM` | verified sender address | optional | example value, line commented out |
| `EMAIL_FROM_NAME` | sender name | optional | `EU-Cowork AI`, line commented out |

<Aside type="note" title="Note on SMTP2GO">
Do not enter the API key. Under **Sending → SMTP Users** create a dedicated SMTP user with its
own password. The sender domain has to be verified, meaning SPF and DKIM are set, otherwise
the server rejects the mail. The host `mail-eu.smtp2go.com` is the EU region,
`mail.smtp2go.com` is the global variant.
</Aside>

The full text search across old conversations always runs. The file search across uploaded
documents additionally needs the Compose profile `filesearch`.

|---|---|---|---|
| `SEARCH` | enables the full text search across conversations | required | `true` |
| `MEILI_NO_ANALYTICS` | switches off the telemetry of Meilisearch | required | `true` |
| `MEILI_HOST` | address of Meilisearch on the internal network | required | `http://meilisearch:7700` |
| `MEILI_MASTER_KEY` | **secret.** Access to Meilisearch | required | `GENERATE`, created by the installer |
| `RAG_PORT` | port of the RAG service on the internal network | required with the `filesearch` profile | `8000` |
| `RAG_API_URL` | address of the RAG service | required with the `filesearch` profile | `http://rag_api:8000` |
| `POSTGRES_PASSWORD` | **secret.** Access to the vector database | required with the `filesearch` profile | `GENERATE`, created by the installer |
| `EMBEDDINGS_PROVIDER` | provider for the embeddings of the file search | optional | empty, line commented out |
| `RAG_OPENAI_BASEURL` | endpoint of the embeddings provider | optional | `https://api.eurouter.ai/api/v1`, line commented out |
| `RAG_OPENAI_API_KEY` | **secret.** Matching key, can refer to `EUROUTER_API_KEY` | optional | reference to `EUROUTER_API_KEY`, line commented out |
| `EMBEDDINGS_MODEL` | embeddings model | optional | `mistral-embed`, line commented out |
| `SEARXNG_INSTANCE_URL` | address of the own metasearch engine | required | `http://searxng:8080` |

## Model providers

| Variable | Purpose | Required | Default |
|---|---|---|---|
| `EUROUTER_API_KEY` | **secret.** Key for EuRouter, the default inference path with EU processing | required | `__SET_YOUR_EUROUTER_KEY__`, enter it yourself |
| `OPENROUTER_API_KEY` | **secret.** Key for OpenRouter. Without a valid key the endpoint still registers, but every call returns HTTP 401 | optional | `__SET_YOUR_OPENROUTER_KEY__` |
| `OPENROUTER_MANAGEMENT_KEY` | **secret.** Only for the tab **Aktivität** (activity) in the admin panel, imports the daily activity per model | optional | empty |
| `OPENROUTER_ACTIVITY_SINCE` | lower bound of this import in the format `YYYY-MM-DD`, useful after a key change | optional | empty |

<Aside type="caution" title="OpenRouter is not EU resident">
OpenRouter is a US gateway and is deliberately included as a non EU option. For purely
European instances, leave the key empty and additionally remove the OpenRouter endpoint
together with its model cards from the `librechat.yaml`.
</Aside>

## Code execution

Code execution is not a service of the main Compose stack, but a separate substack on the
shared Docker network. Two backends are available. Which one is active is decided exclusively
by the base URL.

| Variable | Purpose | Required | Default |
|---|---|---|---|
| `LIBRECHAT_CODE_BASEURL` | selects the code backend | required as soon as code execution is used | line commented out |
| `LIBRECHAT_CODE_API_KEY` | key towards the backend. Uncritical on the internal network, but it has to be set | required as soon as code execution is used | `eucowork-librecode`, line commented out |

The difference lies in the path. Exactly one value may be active:

```bash title="distribution/.env"
LIBRECHAT_CODE_BASEURL=http://code-interpreter:3112/v1   # MIT  /v1
LIBRECHAT_CODE_BASEURL=http://librecode:8000            # OHNE /v1
```

The comments come from the template and are German: `MIT` means with the `/v1` suffix, `OHNE`
means without it. The first line points to the hardened backend with microVM isolation, which
requires `/dev/kvm`. The second line points to the lighter transitional backend with a
prebuilt image.

<Aside type="caution" title="Outbound connections belong in the setup">
Which destinations executed code may reach on the outside is defined at host or network level.
Plan this allowlist before you enable code execution.
</Aside>

## Connector variables

All connector variables are commented out in the template. The customer template deliberately
ships without a preconfigured connector.

The bundled `.env.example` contains a block of its own for every example connector, together
with the Compose profile the matching bridge starts under. Every connector brings its own
variables, usually a base URL or region of the third party system and a secret the bridge
identifies itself with. Which variables those are in detail, and how the account behind them
is set up, is described in the
[connectors](/docs/en/konnektoren/muster) chapter.

Two points apply to all connectors alike. First, the permissions granted in the third party
system are the actual data boundary, and the admin panel additionally governs who gets to see
a bridge at all. Second, these keys never belong in a repository, which is why the `.env`
carries the permissions `600`.

## Admin panel and usage metering

| Variable | Purpose | Required | Default |
|---|---|---|---|
| `USD_EUR_RATE` | conversion rate for the usage dashboard | required | `0.92` |
| `METERING_TOKEN` | **secret.** Service token for the monthly retrieval of the usage aggregates by an operator. Empty means the endpoint is switched off | optional | empty, line commented out |
| `ADMIN_PANEL_SESSION_SECRET` | **secret.** Sessions of the transitional panel, only with the `interim` profile | optional | `GENERATE`, created by the installer |
| `ADMIN_PANEL_SESSION_COOKIE_SECURE` | cookie flag of the transitional panel | optional | `false` |

Freeze the rate in `USD_EUR_RATE` per billing month instead of updating it live. Otherwise the
percentage display fluctuates without anyone having consumed more. The panel freezes the rate
of a completed month anyway, a later change does not alter past months.

The transitional panel is the official AGPL panel of LibreChat. It only starts with the
explicit `interim` profile and is not part of the product. Details are on the
[licenses and origin](/docs/en/referenz/lizenzen) page.

## Multiple instances

These three names are unique across all of Docker. If only one instance runs on the machine,
they stay commented out. If several customer stacks are to run on the same machine, they have
to differ per stack, otherwise the second stack does not start.

| Variable | Purpose | Required | Default |
|---|---|---|---|
| `STACK_NAME` | prefix of all containers of this stack | optional | `eucowork`, line commented out |
| `DOCKER_SUBNET` | own bridge subnet, free of collisions with other stacks and with VPN routes | optional | `172.28.0.0/16`, line commented out |
| `SANDBOX_NETWORK` | own network towards the code interpreter | optional | `eucowork-sandbox`, line commented out |

In addition, `PORT`, `ADMIN_SIDECAR_PORT` and `OFFICE_ADDIN_PORT` have to differ per stack.

<Aside type="danger" title="Never share the sandbox network">
`SANDBOX_NETWORK` is the only place where code from users runs on the machine. Every customer
gets a separate network. Also never shared: database, uploads, the `.env` and the inference
key.
</Aside>

More on this on the [multiple instances](/docs/en/betrieb/mehrere-instanzen) page.

## Variables you should not change

Two values are deliberately set the way they are in the template. Both look harmless, and both
break something when they are changed.

### `DISABLE_COMPRESSION=true`

LibreChat writes its responses as server sent events, but never calls `res.flush()` while
doing so. The compression in Express therefore buffers the entire stream until the end of the
response. A response header was measured after 26 seconds instead of after 0.3 seconds.

For the browser this is barely noticeable. For clients with an idle timeout it aborts every
longer response. This affects the Outlook add-in in particular, whose webview aborts after
around 60 seconds even though the response is still completing on the server. The typical
symptom: the add-in reports a loading error.

There is no downside, because Caddy still compresses for browsers and correctly leaves
`text/event-stream` alone.

### `BAN_VIOLATIONS=true`

Without this flag LibreChat does not check blocks at all. The **Sperren** (block) function in
the admin panel does create an entry, but nobody is locked out. Anyone who considers the block
function credible and sets the value to `false` has a button with no effect.

Related to this: `NON_BROWSER_VIOLATION_SCORE=0`. The anti abuse heuristic of LibreChat rates
requests without a browser typical user agent so highly that it blocks the user and the IP
address immediately. In a stack with sidecars and API access this leads to lockouts. The rate
limiting of sign-in attempts stays active regardless.
