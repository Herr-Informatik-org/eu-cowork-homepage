Web search brings current information from the internet into the chat: prices, news, the state
of the law, details about other companies. This page explains how it is used, which building
blocks it consists of and which of them you choose yourself during setup.

The search framework comes from [LibreChat](https://www.librechat.ai/docs). What we add is the
search engine inside the stack and the preconfiguration.

## How it is used in the chat

There is a switch for web search in the input field. If it is on and the search is fully set
up, the colleague decides for itself when to search. You do not have to write "search the
internet", a question about the current state of something is enough.

The answer is then built on the pages found, with source references. The stored system prompt
demands that explicitly.

## The three building blocks

A working web search consists of more than a search engine.

| Building block | Task | Required |
|---|---|---|
| Search engine | Delivers hits, meaning links and short text excerpts | yes |
| Scraper | Fetches the full text of the pages found | yes |
| Reranker | Sorts the findings by how well they fit | no |

Without a scraper the colleague would only have headlines and two liners, and no reliable
answer can be built from those.

<Aside type="caution" title="Web search is completed during setup">
The customer template brings the search engine along: **SearXNG** runs as its own service in
the stack, `webSearch.searchProvider` is set to `searxng`. You **choose the scraper yourself**,
because which provider fits depends on how you handle data residency; a reranker is optional
and set to `none` out of the box.

Plan this step in firmly: the search tool is only offered to the model once a scraper is
configured. The next two sections show the configuration in full — scraper **and**
`webSearch: true` on every model card you offer.
</Aside>

## For admins: configuring scraper and reranker

Both are maintained in the admin panel under **"Konfiguration → Funktionen"** (configuration,
features tab), in two cards.

**Card "Web-Suche"** (web search)

| Field | Meaning |
|---|---|
| Such-Provider (search provider) | `searxng` or one of the commercial providers LibreChat supports. Shipped is `searxng` |
| SearXNG-URL (SearXNG URL) | Points at the internal service, keep it as the reference `${SEARXNG_INSTANCE_URL}` |
| SearXNG-Schlüssel (SearXNG key) | optional |
| SafeSearch | 0 off, 1 moderate, 2 strict |
| Scraper-Timeout (ms) (scraper timeout) | Patience when fetching a page |

**Card "Web-Suche: Scraper & Reranker"** (web search: scraper and reranker)

| Field | Meaning |
|---|---|
| Scraper | `firecrawl` or one of the commercial providers LibreChat supports. Note in the panel: "Holt die Seiteninhalte zu den Treffern" (fetches the page contents for the hits) |
| Firecrawl-Schlüssel (Firecrawl key), plus one field per remaining provider | Key for the chosen scraper |
| Reranker | `jina`, `cohere` or `none`. The first two strictly require the matching key |
| Jina-Schlüssel, Cohere-Schlüssel | Key for the chosen reranker |

Keys **never** belong in the configuration in plain text. Enter them as `${VARIABLE}` and store
the value in the panel under **"Einstellungen → API-Schlüssel"** (settings, API keys) or in the
`.env` on the server.

<Aside type="note" title="Which scraper fits the EU positioning">
The intended European route is a **self hosted Firecrawl** next to the stack. Then fetching
full text never leaves your infrastructure. You provide the container yourself; the lines for
it are prepared in the customer template and only need to be uncommented.

The hosted variants of the scraper providers are set up quickly but do not process EU resident.
Anyone using them should name that just as clearly as the non EU model cards.
</Aside>

### So that the colleague searches by itself

Two more adjustment points and a restart decide whether a search happens:

<Steps>

1. **Role permission.** In the role editor under **"Werkzeuge"** (tools), the permission
   **"Web-Suche"** (web search) for the roles concerned. In the shipped state
   `interface.webSearch: true` is in the configuration file, so the permission is set.

2. **Card flag.** On the model cards, `webSearch: true` is commented out. Only once you set it
   is the tool attached to the card and the model decides for itself when to use it. This
   belongs on **all** cards you offer.

3. **Restart**, then check in a fresh chat.

   ```bash title="On the server"
   docker compose up -d --force-recreate api
   ```

</Steps>

### How much text reaches the model

The character budget of the search results is controlled by `SEARCH_MAX_LLM_OUTPUT_CHARS` in the
`.env`, default `15000`. Higher means more context for the answer and more tokens per request,
so higher cost. Lower means a thinner basis.

### SearXNG in the stack

SearXNG is a meta search engine that has no results of its own but queries several search
engines and merges the hits. The service runs internally only, without a host port, and uses
around 65 MB when idle.

Three things matter in `distribution/searxng/settings.yml`:

- `formats` contains `json`. Without the JSON format LibreChat cannot read the results.
- `safe_search: 1`, so moderate.
- `secret_key` is replaced during installation by a generated secret.

## Data protection in web search

SearXNG runs on your side, but the search query still goes out. The meta search engine queries
external search engines and returns their hits. What happens in the process and what does not:

| | |
|---|---|
| Goes outside | the search term, plus the pages fetched by the scraper |
| Does **not** go outside | who searched. The identity of the person stays with you |
| Stays with you | the conversation, the documents, the answer |

<Aside type="note" title="Wording for training and privacy notices">
Put precisely, the statement reads: storage and inference run where you operate the stack; the
search query itself goes to external search engines, and it does so without user identity.
Anyone describing web search in a privacy notice is best served by taking that distinction
over verbatim.
</Aside>
