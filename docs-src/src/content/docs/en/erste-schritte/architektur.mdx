EU Cowork AI runs as a Docker Compose stack on a Linux machine. This page shows the setup in
broad strokes. It describes the path a request takes and the decisions behind it — not the
setup in detail.

## The data flow

<DiagrammArchitektur />

Two things matter here. First, every path from the outside goes through the reverse proxy; the
other services accept no connections from the network. Second, accounts, conversations and
files stay on your server, while for the model responses themselves the provider is called.

## The layers

**Reverse proxy.** The only entry point from the outside. It terminates TLS, takes care of the
certificate and routes the requests to the services behind it.

**Application.** This is [LibreChat](https://www.librechat.ai). The service serves the
interface, talks to the model providers, runs the agents and processes uploaded files.

**Data storage.** Accounts, conversations, messages, agents and logs live in the database of
the instance, alongside a search index across your own chats and the uploaded files on the same
server. The database is the source of truth, the search index can be rebuilt from it at any
time.

**What EU Cowork AI adds.** Around LibreChat sit our own services for administration,
permissions and usage overview, plus the connection to third party systems. They are reachable
only inside the instance and are not exposed to the network.

**Outside the instance.** For the model responses the inference provider is called, for web
search external search engines. If code execution is switched on, it runs in a separate,
isolated environment next to the application.

<Aside type="note" title="What comes from LibreChat">
Chat, agents, file handling and model connectivity come from LibreChat and are publicly
documented there. The additions from EU Cowork AI sit on top without changing the core, which
is why updates from LibreChat remain possible.
</Aside>

## Why one instance per customer

LibreChat does not know about tenants. The separation therefore sits below the application: one
customer is one instance with its own database, its own search index, its own files, its own
configuration and its own inference key. Whether two instances share a machine is after that a
pure question of cost and risk.

| May be shared | Must never be shared |
|---|---|
| Docker images and their layers | database, search index, files |
| a shared reverse proxy | configuration and all secrets |
| monitoring, backup schedule, system updates | the environment for code execution |
| | the inference key, otherwise the cost per customer cannot be attributed |

<Aside type="note" title="The setup documents">
Which services an instance brings along in detail, how they are configured and what to watch
in operation is described in the documents that come with the delivery.
</Aside>
