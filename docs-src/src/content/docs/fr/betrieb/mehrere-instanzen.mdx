Pour un client de quelques personnes, une machine virtuelle dédiée est du gaspillage : la charge
de base d’une instance est faible. Plusieurs instances peuvent donc se partager une machine.
Cette page décrit où passe alors la ligne de séparation. Elle s’adresse aux prestataires
informatiques qui exploitent plusieurs clients.

## La frontière entre clients est l’instance, pas la machine

Un client, c’est exactement **une instance** : base de données propre, recherche plein texte
propre, téléversements propres, configuration propre, secrets propres, backend propre pour
l’exécution de code. Ce point n’est pas négociable et découle directement de l’architecture :
l’application elle-même ne connaît pas la notion de client. La séparation doit donc se situer en
dessous de l’application, et c’est là qu’elle est nette.

Que deux instances partagent la même machine devient dès lors une question de coûts et de
risques, non plus une question d’architecture.

## Ce qui n’est jamais partagé

| Domaine | Raison |
|---|---|
| Base de données | Contient les comptes, les conversations et les écritures d’un client |
| Téléversements et images | Contenus clients |
| Configuration et tous les secrets | Un secret commun annule toute séparation |
| Backend pour l’exécution de code | Le seul endroit où s’exécute du code des utilisateurs |
| Clé d’inférence | Avec une clé partagée, les coûts par client ne sont plus dissociables |
| Service propre pour la recherche web | Voit les requêtes de recherche et donc des contenus des utilisateurs |

## Ce qui peut être partagé

- **Les images Docker et leurs couches.** C’est la plus grande économie : les images ne sont
  conservées qu’une seule fois.
- **Un reverse proxy en amont**, seul service à occuper les ports publics.
- **La supervision de l’hôte, la planification des sauvegardes et les mises à jour de sécurité
  automatiques.**

Le noyau, le service Docker et les ressources matérielles sont eux aussi partagés,
inévitablement. C’est la véritable limite de ce mode d’exploitation : un redémarrage dû à une
mise à jour du noyau touche tous les clients de la machine.

<Aside type="caution" title="L’exécution de code est le point dur">
Partout ailleurs, la plateforme n’exécute que son propre code ; les utilisateurs n’ont pas accès
à la ligne de commande. L’exception est l’exécution de code. Elle reçoit donc, par instance, un
environnement propre et séparé. Sur une machine partagée, le mode d’exploitation le plus
fortement cloisonné est en outre le meilleur choix.
</Aside>

## Ce qui doit être unique par instance

Plusieurs instances sur une machine entrent en collision si elles partagent des noms ou des
adresses. Chaque instance a donc besoin, de bout en bout, de ses propres identifiants et de ses
propres espaces de stockage. Quelles valeurs sont concernées en détail et comment elles se
définissent figure dans le manuel d’exploitation, qui est fourni avec le paquet de livraison. Les
clients le reçoivent en même temps que leur accès.

## Quand une machine dédiée

- **Petite clientèle :** plusieurs instances sur une machine commune, selon la taille trois à
  cinq clients.
- **Clientèle moyenne :** une machine dédiée par client.
- **Grande clientèle, secteur réglementé, infrastructure dédiée garantie par contrat ou
  raccordement ERP propre :** une machine dédiée, dimensionnée en conséquence.

Les valeurs indicatives concrètes pour la mémoire vive, le CPU et l’espace disque figurent sous
[Configuration requise](/docs/fr/erste-schritte/systemanforderungen).

## Exploitation avec plusieurs instances

- **Une sauvegarde par instance.** Chaque instance sauvegarde exactement ses propres données, à
  des horaires décalés.
- **Une mise à jour par instance.** Les clients peuvent faire tourner des versions différentes.
  C’est précisément à cela que servent les versions figées, voir
  [Mise à jour](/docs/fr/betrieb/aktualisieren).
- **Supervision.** La première limite est l’espace disque, pas la mémoire vive. Une alerte à
  partir de 70 pour cent d’occupation est judicieuse, tout comme la surveillance des services qui
  redémarrent.
- **Offboarding.** Arrêter l’instance, tirer une archive, supprimer les données. Aucune
  intervention dans d’autres instances, aucun nettoyage dans une base de données commune. C’est
  là le véritable gain de la frontière d’instance.
