Wie bei LibreChat üblich wird eine Instanz über eine Umgebungsdatei konfiguriert. Der
Auslieferung liegt eine kommentierte Vorlage bei, aus der der Installer beim ersten Lauf die
tatsächliche Konfiguration erzeugt.

<Aside type="danger" title="Die Konfigurationsdatei bleibt auf dem Server">
Sie enthält sämtliche Zugangsdaten der Instanz. Sie gehört nie in ein Repository, nie in ein
Ticket und nie in eine Support-Anfrage.
</Aside>

## Was Sie selbst setzen

Der weitaus grösste Teil der Vorlage ist so vorbelegt, dass eine Instanz startet. Selbst
angeben müssen Sie im Wesentlichen drei Dinge:

- **die Domain**, unter der die Instanz erreichbar ist. Solange hier der Vorgabewert steht,
  laufen Einladungslinks nur auf dem Server selbst.
- **den Zugangsschlüssel des Modell-Anbieters.** Ohne ihn startet die Instanz zwar, aber jede
  Modellanfrage scheitert.
- **optional die Zugangsdaten für den Mailversand.** Ohne sie gibt es keine Verifikations- und
  Einladungsmails, eine Einladung liefert dann nur einen Link zum Kopieren.

## Geheimnisse

Die kryptografischen Geheimnisse einer Instanz erzeugt der Installer beim ersten Lauf selbst
und legt sie geschützt ab. Sie müssen dafür nichts tun.

<Aside type="caution" title="Beim Umzug auf einen neuen Server">
Die bestehende Konfiguration muss übernommen werden. Wird sie stattdessen neu erzeugt, lassen
sich zuvor verschlüsselt gespeicherte Zugangsdaten nicht mehr lesen, und alle Nutzer müssen
ihre Konnektor-Verbindungen neu aufbauen. Das mitgelieferte Backup-Werkzeug nimmt die
Konfiguration deshalb mit.
</Aside>

## Vollständige Referenz

Welche Einträge es im Einzelnen gibt, was sie bewirken und welche davon für eine bestimmte
Ausbaustufe nötig sind, steht in den Betriebsunterlagen, die der Auslieferung beiliegen.
Kunden erhalten sie zusammen mit dem Zugang. Die Vorlage selbst ist ebenfalls kommentiert.

Für alles, was Standard von LibreChat ist, gilt zusätzlich die dortige Dokumentation unter
[www.librechat.ai/docs](https://www.librechat.ai/docs).
