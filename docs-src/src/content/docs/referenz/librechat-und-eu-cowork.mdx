EU Cowork AI ist keine Neuentwicklung von Grund auf. Die Chat-Oberfläche und ein grosser Teil
der Anwendungslogik stammen aus einem bestehenden Open-Source-Projekt, unsere Arbeit liegt in
der Schicht darum herum. Diese Seite trennt beides sauber, damit Sie wissen, wo Sie eine
Antwort suchen müssen und wem Sie einen Fehler melden.

## Was LibreChat ist

[LibreChat](https://www.librechat.ai) ist eine quelloffene Chat-Plattform unter der
**MIT-Lizenz**. Sie bringt die Oberfläche, die Anbindung an beliebige Modell-Anbieter, das
Agenten- und Dateisystem sowie eine Administrations-Schnittstelle mit. Das Projekt ist
ausgereift und wird aktiv weiterentwickelt.

Unser laufender Stack verwendet das **offizielle LibreChat-Image in einer festgelegten, von uns
getesteten Fassung**, nicht einfach den jeweils neuesten Stand. Wer die Plattform nur betreiben
will, baut LibreChat also nie aus dem Quellcode. Ein Versionssprung ist eine bewusste Handlung
mit einer eigenen Prüfliste.

## Was von LibreChat kommt

| Bereich | Was es umfasst |
|---|---|
| **Chat** | Streaming, Verlauf, automatische Titel, Verzweigen von Konversationen, geteilte Links, temporäre Chats, Mehrfach-Chats |
| **Agenten** | Agenten anlegen und nutzen, Werkzeug-Auswahl pro Agent, Agent-Marketplace |
| **Skills** | hinterlegte Standard-Prozesse, die ein Modell auf Zuruf abarbeitet |
| **Memory** | Langzeitgedächtnis über Konversationen hinweg, mit Opt-out im Chat |
| **Artifacts** | React, HTML, Mermaid und SVG direkt im Chat, unabhängig von der Code-Ausführung |
| **Dateien** | Upload als Kontext, Bildverständnis, die Dateisuche über hochgeladene Dokumente |
| **Web-Suche** | das Gerüst dafür samt Anbindung einer Suchmaschine |
| **Code-Ausführung** | die steckbare Schnittstelle zum Sandbox-Backend |
| **MCP-Client** | die Fähigkeit, mit Konnektoren über das Model Context Protocol zu sprechen |
| **Presets und Prompts** | Prompt-Bibliothek, Voreinstellungen, Lesezeichen |
| **Volltextsuche** | Suche über frühere Konversationen |
| **Administration** | die Administrations-Schnittstelle samt fortlaufender Audit-Kette |
| **Identität** | OIDC inklusive Entra ID, LDAP und SAML, dazu der Rollen-Abgleich |
| **Verbrauchsmessung** | Token-Erfassung und Guthaben pro Person |

## Was wir gebaut haben

| Baustein | Was es tut |
|---|---|
| **Admin-Panel** | eigenes, permissiv lizenziertes Panel gegen die MIT-Schnittstelle von LibreChat, dazu ein begleitender Dienst für alles, was diese Schnittstelle nicht kann: Verbrauch in Euro, gemeinsames Monatsbudget, Aufbewahrung, Datenexport und Löschung pro Konto |
| **MCP-Gateway** | Rechteprüfung und Protokoll vor jedem Zugriff auf ein Fremdsystem, entlang der Kette Benutzer, Rolle, Gruppe, Standard. Fällt die Prüfung aus, wird verweigert |
| **Model-Router** | verteilt Anfragen je nach Aufgabe auf unterschiedliche Modelle und Denkaufwände |
| **Beispiel-Konnektor-Brücke** | ausschliesslich lesender Zugang zu einem Fachsystem, als Vorlage für eigene Anbindungen |
| **Outlook-Add-in** | seitliches Chat-Pane in Outlook mit der geöffneten Mail als Kontext, gegen dieselbe Instanz und dieselben Rechte |
| **Modellkarten und Systemprompt** | die kuratierte Auswahl im Modell-Picker und der deutsche Systemprompt, der serverseitig eingefügt wird |
| **Installationspaket** | Compose-Stack, Server-Vorbereitung, Installer, Backup und Umzug, Reverse-Proxy, Branding |
| **Konfigurationsprofile** | Kunden-Template gegenüber einer Instanz mit Konnektoren, dazu die Ausbaustufen für Dateisuche, Konnektoren und TLS |

<Aside type="note" title="Code-Ausführung">
Für die Code-Ausführung bindet EU Cowork AI etablierte Backends ein, statt einen eigenen Runner
mitzuliefern — wahlweise eine gehärtete Variante mit microVM-Isolation oder eine leichtere
Übergangsvariante. Welche Ziele ausgeführter Code nach aussen erreichen darf, legen Sie auf
Host- oder Netzebene fest.
</Aside>

## Warum der Fork dünn bleibt

LibreChat ist geforkt, aber der Fork bleibt absichtlich nah am Original. Der Grund ist
schlicht: je weiter ein Fork abdriftet, desto teurer wird jede Aktualisierung, und irgendwann
findet sie nicht mehr statt. Eine Chat-Plattform, die zwei Jahre hinter dem Original
zurückhängt, ist kein Vorteil, sondern ein Risiko.

Daraus folgt eine feste Reihenfolge, in der eine Änderung versucht wird:

1. **Konfiguration.** Lässt sich das in der `librechat.yaml`, in der Umgebungsdatei oder im
   Admin-Panel lösen?
2. **CSS.** Reicht eine Anpassung der Darstellung?
3. **Kleiner Patch.** Eine eng begrenzte Änderung im Fork.
4. **Eigene Komponente.** Erst wenn nichts anderes trägt.

Alles, was ohne Eingriff in LibreChat lösbar ist, wird deshalb als eigener Dienst daneben
gebaut. Diese Dienste heissen Sidecars: eigenständige Container mit eigenem Lebenszyklus, die
über normale Netzwerk-Schnittstellen mit LibreChat sprechen. Das Admin-Panel, das
MCP-Gateway, die mitgelieferte Konnektor-Brücke und das Outlook-Add-in sind alle so gebaut.

Praktisch heisst das für Sie: Ein Update von LibreChat berührt unsere Dienste nicht, und eine
neue Fassung des Admin-Panels berührt LibreChat nicht. Beides wird getrennt aktualisiert. Eine
Freigabe von EU Cowork AI ist immer ein getestetes Paar aus einer bestimmten LibreChat-Fassung
und bestimmten Sidecar-Ständen.

## Die Datei `librechat.yaml`

Die zentrale Konfigurationsdatei der Chat-Anwendung ist die `librechat.yaml`. Sie steuert,
welche Modelle es gibt, wie die Oberfläche aussieht, welche Konnektoren eingebunden sind und
wie die Web-Suche arbeitet.

**Die vollständige Feldreferenz steht bei LibreChat**, unter
[www.librechat.ai/docs](https://www.librechat.ai/docs). Wie die Datei in einer Auslieferung
vorbelegt ist, steht in den mitgelieferten Betriebsunterlagen.

Zwei Mechanikregeln, die immer wieder für Überraschungen sorgen:

- **Der `interface`-Block ist global.** Seine Werte werden beim Start in alle Rollen
  geschrieben und bei jedem Neustart erneut gesetzt. Unterschiede pro Rolle gehören deshalb in
  den Rollen-Editor des Admin-Panels, nicht in die Datei.
- **`endpoints.agents.capabilities` ersetzt die Standardliste**, es mischt sich nicht mit ihr.
  Wer dort etwas einträgt, muss alles aufzählen, was erhalten bleiben soll.

<Aside type="tip" title="Das Panel gewinnt gegen die Datei">
Was Sie im Admin-Panel unter **Konfiguration** setzen, liegt als Override über der
`librechat.yaml` und wirkt sofort, ohne Neustart. Betroffene Abschnitte tragen im Panel den
Hinweis **aus DB-Override**. Wer eine Änderung in der Datei macht und sie nicht sieht, hat
vermutlich einen Override darüber liegen.
</Aside>

Die Aufteilung ist einfach: Alles, was die Chat-Anwendung selbst betrifft, steht bei
LibreChat. Alles, was mit Betrieb, Rechten, Verbrauch und Konnektoren zu tun hat, steht hier.

Für Chat-Funktionen im Detail, Agenten, Skills, Memory, Artifacts und die vollständige
Feldreferenz der Konfiguration:

OIDC, LDAP und SAML.

## Wohin mit einem Fehler

| Der Fehler betrifft | Zuständig |
|---|---|
| Chat-Oberfläche, Agenten, Modell-Anbindung, Dateiverarbeitung | LibreChat |
| Admin-Panel, Verbrauchsanzeige, Budget, Aufbewahrung | EU Cowork AI |
| Rechte auf Konnektoren, Protokoll der Werkzeug-Aufrufe | EU Cowork AI |
| Installation, Backup, Umzug, Compose-Stack, TLS | EU Cowork AI |
| Outlook-Add-in | EU Cowork AI |

Die Lizenzen aller beteiligten Bausteine stehen unter
[Lizenzen und Herkunft](/docs/referenz/lizenzen).
