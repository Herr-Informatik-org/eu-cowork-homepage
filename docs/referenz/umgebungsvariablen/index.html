Umgebungsvariablen

Alle Einstellungen einer Instanz stehen in einer einzigen Datei: distribution/.env. Diese Seite listet jede Variable aus der mitgelieferten Vorlage distribution/.env.example auf, gruppiert nach Themen. Sie richtet sich an alle, die eine Instanz einrichten oder betreiben.

Der Installer legt die .env beim ersten Lauf aus der Vorlage an, erzeugt die Geheimnisse und setzt die Rechte auf 600. Die Datei gehört nie in ein Repository und nie in ein Ticket.

Keine echten Werte in dieser Dokumentation

Auf dieser Seite stehen ausschliesslich die Platzhalter aus der Vorlage. Ein Wert wie __SET_YOUR_EUROUTER_KEY__ ist genau das: ein Platzhalter, den Sie auf Ihrem Server durch Ihren eigenen Schlüssel ersetzen. Geben Sie Inhalte Ihrer echten .env nie weiter.

Die drei Dinge, die Sie wirklich anfassen müssen

Abschnitt betitelt „Die drei Dinge, die Sie wirklich anfassen müssen“

Der Rest der Datei ist so vorbelegt, dass eine Instanz startet. Drei Bereiche müssen Sie selbst setzen.

Kurzfassung

  1. EUROUTER_API_KEY eintragen, sonst antwortet kein Modell.
  2. DOMAIN_CLIENT, DOMAIN_SERVER und EUCOWORK_DOMAIN auf Ihre Domain setzen, sobald die Instanz nicht mehr nur lokal läuft.
  3. In Produktion hinter Caddy API_BIND=127.0.0.1 setzen.

EUROUTER_API_KEY ist der einzige Wert, den ein Standardkunde zwingend selbst eintragen muss. Ohne ihn startet der Stack zwar, aber jede Modellanfrage scheitert.

Die drei Domain-Variablen stehen ab Werk auf localhost. DOMAIN_CLIENT ist die URL, die der Browser sieht, und zugleich die Basis für Einladungslinks. DOMAIN_SERVER ist die Server-URL und damit die Basis der Redirect-URI für Konnektoren mit Anmeldung pro Person. EUCOWORK_DOMAIN trägt Caddy und das Office-Manifest. Bleiben sie auf localhost, verschicken Sie Einladungen mit einem Link, der nur auf dem Server selbst funktioniert.

API_BIND steht ab Werk auf 0.0.0.0, weil das lokal bequem ist. In Produktion mit Caddy gehört der Wert auf 127.0.0.1. Sonst ist LibreChat zusätzlich direkt per HTTP auf <server-ip>:3080 erreichbar, also an TLS vorbei, mit Passwörtern im Klartext im Netz. Die Firewall hilft dagegen nicht: von Docker veröffentlichte Ports umgehen die ufw-Regeln. Panel und Add-in binden bereits ab Werk auf 127.0.0.1.

Geheimnisse

Abschnitt betitelt „Geheimnisse“

Diese Werte erzeugt install.sh beim ersten Lauf selbst. Sie müssen dafür nichts tun.

Variable Wofür
CREDS_KEY verschlüsselt gespeicherte Zugangsdaten der Nutzer, etwa eine Konnektor-Verbindung
CREDS_IV Initialisierungsvektor zur Verschlüsselung
JWT_SECRET signiert die Sitzungs-Token
JWT_REFRESH_SECRET signiert die Erneuerungs-Token
MEILI_MASTER_KEY Zugang zur Volltextsuche
POSTGRES_PASSWORD Zugang zur Vektordatenbank der Dateisuche
SEARXNG_SECRET Zugang zur eigenen Metasuchmaschine
ADMIN_PANEL_SESSION_SECRET Sitzungen des Übergangs-Panels

Diese Werte müssen Sie selbst eintragen, der Installer kann sie nicht erfinden: EUROUTER_API_KEY, wahlweise OPENROUTER_API_KEY, die SMTP-Zugangsdaten sowie sämtliche Konnektor-Schlüssel.

Beim Umzug auf einen neuen Server

CREDS_KEY und CREDS_IV müssen aus der alten .env übernommen werden. Werden sie neu erzeugt, lassen sich die gespeicherten Zugangsdaten nicht mehr entschlüsseln und alle Nutzer müssen ihre Konnektor-Verbindungen neu aufbauen.

E-Mail

Abschnitt betitelt „E-Mail“

Der Mailversand ist optional und in der Vorlage vollständig auskommentiert. Ein Satz Zugangsdaten treibt zwei Wege: die Verifikation und den Passwort-Reset von LibreChat sowie den automatischen Versand der Einladungen aus dem Admin-Panel. Ohne diese Werte gibt es keinen Mailversand, die Einladung liefert dann nur einen Link zum Kopieren.

Variable Zweck Pflicht Standard
EMAIL_SERVICE benannter Dienst statt Host und Port, dann entfallen die beiden nächsten Zeilen optional leer, Zeile auskommentiert
EMAIL_HOST SMTP-Server optional mail-eu.smtp2go.com, Zeile auskommentiert
EMAIL_PORT SMTP-Port. 2525, 587 und 8025 sprechen STARTTLS, 465 und 8465 sprechen TLS optional 2525, Zeile auskommentiert
EMAIL_ENCRYPTION starttls oder tls, passend zum Port optional starttls, Zeile auskommentiert
EMAIL_USERNAME Geheimnis. SMTP-Benutzer optional __SET_SMTP2GO_SMTP_USER__, Zeile auskommentiert
EMAIL_PASSWORD Geheimnis. SMTP-Passwort optional __SET_SMTP2GO_SMTP_PASSWORD__, Zeile auskommentiert
EMAIL_FROM verifizierte Absenderadresse optional Beispielwert, Zeile auskommentiert
EMAIL_FROM_NAME Absendername optional EU-Cowork AI, Zeile auskommentiert

Hinweis zu SMTP2GO

Nicht den API-Schlüssel eintragen. Unter Sending → SMTP Users einen eigenen SMTP-Benutzer mit eigenem Passwort anlegen. Die Absender-Domain muss verifiziert sein, also SPF und DKIM gesetzt, sonst lehnt der Server die Mail ab. Der Host mail-eu.smtp2go.com ist die EU-Region, mail.smtp2go.com ist die globale Variante.

OpenRouter ist nicht EU-resident

OpenRouter ist ein US-Gateway und bewusst als Nicht-EU-Option eingebunden. Für rein europäische Instanzen den Schlüssel leer lassen und zusätzlich den OpenRouter-Endpunkt samt Modellkarten aus der librechat.yaml entfernen.

Konnektor-Variablen

Abschnitt betitelt „Konnektor-Variablen“

Alle Konnektor-Variablen sind in der Vorlage auskommentiert. Das Kunden-Template liefert bewusst keinen vorkonfigurierten Konnektor aus.

Die mitgelieferte .env.example enthält für jeden Beispiel-Konnektor einen eigenen Block, zusammen mit dem Compose-Profil, unter dem die zugehörige Brücke startet. Jeder Konnektor bringt seine eigenen Variablen mit, meist eine Basis-URL oder Region des Fremdsystems und ein Geheimnis, mit dem sich die Brücke dort ausweist. Welche Variablen das im Einzelnen sind und wie das Konto dahinter eingerichtet wird, steht im Kapitel Konnektoren.

Zwei Punkte gelten für alle Konnektoren gleich. Erstens ist die Rechtevergabe im Fremdsystem die eigentliche Datengrenze, das Admin-Panel regelt darüber hinaus, wer eine Brücke überhaupt sieht. Zweitens gehören diese Schlüssel nie in ein Repository, die .env trägt deshalb die Rechte 600.

Abschnitt betitelt „Admin-Panel und Verbrauchsmessung“

Den Kurs in USD_EUR_RATE pro Abrechnungsmonat einfrieren statt live nachzuführen. Sonst schwankt die Prozentanzeige, ohne dass jemand mehr verbraucht hätte. Das Panel friert den Kurs eines abgeschlossenen Monats ohnehin ein, ein späterer Wechsel ändert alte Monate nicht.

Das Übergangs-Panel ist das offizielle AGPL-Panel von LibreChat. Es startet nur mit dem ausdrücklichen Profil interim und ist nicht Teil des Produkts. Details dazu stehen unter Lizenzen und Herkunft.

Mehrfach-Instanzen

Abschnitt betitelt „Mehrfach-Instanzen“

Diese drei Namen sind Docker-weit eindeutig. Läuft nur eine Instanz auf der Maschine, bleiben sie auskommentiert. Sollen mehrere Kunden-Stacks auf derselben Maschine laufen, müssen sie sich pro Stack unterscheiden, sonst startet der zweite Stack nicht.

Variable Zweck Pflicht Standard
STACK_NAME Präfix aller Container dieses Stacks optional eucowork, Zeile auskommentiert
DOCKER_SUBNET eigenes Bridge-Subnetz, kollisionsfrei zu anderen Stacks und zu VPN-Routen optional 172.28.0.0/16, Zeile auskommentiert
SANDBOX_NETWORK eigenes Netz zum Code-Interpreter optional eucowork-sandbox, Zeile auskommentiert

Zusätzlich müssen PORT, ADMIN_SIDECAR_PORT und OFFICE_ADDIN_PORT pro Stack unterschiedlich sein.

Das Sandbox-Netz nie teilen

SANDBOX_NETWORK ist die einzige Stelle, an der Code von Nutzern auf der Maschine läuft. Jeder Kunde bekommt ein eigenes Netz. Ebenfalls nie geteilt werden: Datenbank, Uploads, die .env und der Inferenz-Schlüssel.

Variablen, die man nicht ändern sollte

Abschnitt betitelt „Variablen, die man nicht ändern sollte“

Zwei Werte stehen in der Vorlage bewusst so, wie sie stehen. Beide sehen harmlos aus, und beide brechen etwas, wenn man sie umstellt.

DISABLE_COMPRESSION=true

Abschnitt betitelt „DISABLE_COMPRESSION=true“

LibreChat schreibt seine Antworten als Server-Sent-Events, ruft dabei aber nie res.flush() auf. Die Kompression von Express puffert deshalb den gesamten Datenstrom bis zum Ende der Antwort. Gemessen wurde ein Antwort-Header nach 26 Sekunden statt nach 0,3 Sekunden.

Für den Browser fällt das kaum auf. Für Clients mit einem Leerlauf-Zeitlimit bricht damit jede längere Antwort ab. Das betrifft besonders das Outlook-Add-in, dessen Webview nach rund 60 Sekunden abbricht, obwohl die Antwort serverseitig fertig läuft. Typisches Fehlerbild: das Add-in meldet einen Ladefehler.

Ein Nachteil entsteht nicht, denn Caddy komprimiert für Browser weiterhin und lässt text/event-stream korrekt in Ruhe.

BAN_VIOLATIONS=true

Abschnitt betitelt „BAN_VIOLATIONS=true“

Ohne dieses Flag prüft LibreChat Sperren überhaupt nicht. Die Funktion Sperren im Admin-Panel legt zwar einen Eintrag an, aber niemand wird ausgesperrt. Wer die Sperrfunktion für glaubwürdig hält und den Wert auf false setzt, hat eine Schaltfläche ohne Wirkung.

Verwandt dazu: NON_BROWSER_VIOLATION_SCORE=0. Die Anti-Missbrauchs-Heuristik von LibreChat bewertet Anfragen ohne browsertypischen User-Agent so hoch, dass sie Benutzer und IP-Adresse sofort sperrt. In einem Stack mit Sidecars und API-Zugriffen führt das zu Aussperrungen. Die Begrenzung von Anmeldeversuchen bleibt davon unberührt aktiv.
