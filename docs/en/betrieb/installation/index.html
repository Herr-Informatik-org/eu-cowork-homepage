Installation

The setup is carried out by an installation script from the delivery package. It creates the configuration, generates the required secrets and starts the application. The prerequisite is a prepared server, see Prepare the server.

What the installer takes care of

Section titled “What the installer takes care of”
  • It checks the prerequisites on the machine and aborts if something fundamental is missing.
  • It creates the configuration file from the supplied template and sets all secrets to freshly generated random values. The file is readable only by the service user.
  • It sets up the directories for uploads, logs and data with the correct permissions.
  • It fetches the images and starts the application.
  • It reports at the end which values still have to be entered by hand. Only the names of the values are reported, never their contents.

Secure the generated secrets

Some of the generated values decrypt what is stored encrypted in the database: the OAuth tokens with which your staff connected a connector, and the API keys stored in the panel. If these values are lost, or regenerated during a migration instead of carried over, the affected data is irretrievably unreadable. Every person would then have to rebuild every connection. The regular backup contains the configuration file and therefore these values, see Backup and migration.

The only mandatory value

Section titled “The only mandatory value”

For a standard installation you enter exactly one value yourself: the key of the inference provider with EU processing. The installer explicitly points this out at the end. Everything else is optional — a second option for models, the connectors, e-mail delivery and the backend for code execution.

What remains manual

Section titled “What remains manual”
  • Set the DNS records and choose the TLS variant, see Domain and certificate.
  • Set the domain lock for registration, see Configuration.
  • Define role permissions and model cards in the admin panel.
  • Deliberately grant access for each connector in the panel instead of leaving it open.
  • Set up the backup, see Backup and migration.

After the first start

Section titled “After the first start”

  1. Open the chat. At the address the installer prints at the end.

  2. Create the first account. Register in the chat. The first registered account of an instance automatically receives the ADMIN role.

  3. Check the admin panel. You sign in with the account you just created. The panel has no user management and no password of its own.

  4. Close off access. Set the domain lock so that only people from your e-mail domain can register.

  5. Create a second admin account. Not only the personal one, otherwise you lock yourself out when it matters.

  6. Set up the backup. Back up once by hand and then schedule the backup.

Detailed instructions in the operations manual

The invocation, the options and the complete list of configuration values are in the operations manual that comes with the delivery package.
