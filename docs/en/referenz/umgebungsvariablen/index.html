Environment variables

All settings of an instance live in a single file: distribution/.env. This page lists every variable from the shipped template distribution/.env.example, grouped by topic. It is written for everyone who sets up or operates an instance.

The installer creates the .env from the template on the first run, generates the secrets and sets the permissions to 600. The file never belongs in a repository and never in a ticket.

No real values in this documentation

This page contains only the placeholders from the template. A value like __SET_YOUR_EUROUTER_KEY__ is exactly that: a placeholder that you replace with your own key on your server. Never pass on the contents of your real .env.

What the columns mean

Section titled “What the columns mean”
Column Meaning
Variable the name exactly as it appears in the .env
Purpose what the value is needed for
Required whether the instance runs without this value. Some values are only needed with a particular Compose profile
Default the value from .env.example. commented out means the line starts with # and is therefore inactive

The three things you really have to touch

Section titled “The three things you really have to touch”

The rest of the file is preset so that an instance starts. Three areas you have to set yourself.

Short version

  1. Enter EUROUTER_API_KEY, otherwise no model responds.
  2. Set DOMAIN_CLIENT, DOMAIN_SERVER and EUCOWORK_DOMAIN to your domain as soon as the instance no longer runs only locally.
  3. In production behind Caddy, set API_BIND=127.0.0.1.

EUROUTER_API_KEY is the only value a standard customer has to enter themselves. Without it the stack does start, but every model request fails.

The three domain variables are set to localhost out of the box. DOMAIN_CLIENT is the URL the browser sees and at the same time the basis for invitation links. DOMAIN_SERVER is the server URL and therefore the basis of the SharePoint redirect URI. EUCOWORK_DOMAIN is used by Caddy and by the Office manifest. If they stay on localhost, you send invitations with a link that only works on the server itself.

API_BIND is set to 0.0.0.0 out of the box, because that is convenient locally. In production with Caddy the value belongs on 127.0.0.1. Otherwise LibreChat is additionally reachable directly over HTTP at <server-ip>:3080, bypassing TLS, with passwords in clear text on the network. The firewall does not help against that: ports published by Docker bypass the ufw rules. Panel and add-in already bind to 127.0.0.1 out of the box.

Secrets

Section titled “Secrets”

These values are generated by install.sh on the first run. You do not have to do anything for them.

Variable What for
CREDS_KEY encrypts the stored credentials of the users, for example the SharePoint connection
CREDS_IV initialization vector for the encryption
JWT_SECRET signs the session tokens
JWT_REFRESH_SECRET signs the refresh tokens
MEILI_MASTER_KEY access to the full text search
POSTGRES_PASSWORD access to the vector database of the file search
SEARXNG_SECRET access to the own metasearch engine
ADMIN_PANEL_SESSION_SECRET sessions of the transitional panel

These values you have to enter yourself, the installer cannot invent them: EUROUTER_API_KEY, optionally OPENROUTER_API_KEY, the SMTP credentials and all connector keys.

When migrating to a new server

CREDS_KEY and CREDS_IV have to be taken over from the old .env. If they are generated anew, the stored credentials can no longer be decrypted and all users have to set up their SharePoint connection again.

Email

Section titled “Email”

Mail delivery is optional and fully commented out in the template. One set of credentials drives two paths: the verification and password reset of LibreChat, and the automatic sending of the invitations from the admin panel. Without these values there is no mail delivery, and an invitation then only produces a link to copy.

Variable Purpose Required Default
EMAIL_SERVICE a named service instead of host and port, then the next two lines are not needed optional empty, line commented out
EMAIL_HOST SMTP server optional mail-eu.smtp2go.com, line commented out
EMAIL_PORT SMTP port. 2525, 587 and 8025 speak STARTTLS, 465 and 8465 speak TLS optional 2525, line commented out
EMAIL_ENCRYPTION starttls or tls, matching the port optional starttls, line commented out
EMAIL_USERNAME secret. SMTP user optional __SET_SMTP2GO_SMTP_USER__, line commented out
EMAIL_PASSWORD secret. SMTP password optional __SET_SMTP2GO_SMTP_PASSWORD__, line commented out
EMAIL_FROM verified sender address optional example value, line commented out
EMAIL_FROM_NAME sender name optional EU-Cowork AI, line commented out

Note on SMTP2GO

Do not enter the API key. Under Sending → SMTP Users create a dedicated SMTP user with its own password. The sender domain has to be verified, meaning SPF and DKIM are set, otherwise the server rejects the mail. The host mail-eu.smtp2go.com is the EU region, mail.smtp2go.com is the global variant.

OpenRouter is not EU resident

OpenRouter is a US gateway and is deliberately included as a non EU option. For purely European instances, leave the key empty and additionally remove the OpenRouter endpoint together with its model cards from the librechat.yaml.

Code execution

Section titled “Code execution”

Code execution is not a service of the main Compose stack, but a separate substack on the shared Docker network. Two backends are available. Which one is active is decided exclusively by the base URL.

Variable Purpose Required Default
LIBRECHAT_CODE_BASEURL selects the code backend required as soon as code execution is used line commented out
LIBRECHAT_CODE_API_KEY key towards the backend. Uncritical on the internal network, but it has to be set required as soon as code execution is used eucowork-librecode, line commented out

The difference lies in the path. Exactly one value may be active:

The comments come from the template and are German: MIT means with the /v1 suffix, OHNE means without it. The first line points to the hardened backend with microVM isolation, which requires /dev/kvm. The second line points to the lighter transitional backend with a prebuilt image.

Open gap

The allowlist for outbound connections from code execution is still missing. The own hardened runner with an egress proxy is planned, but not built.

Admin panel and usage metering

Section titled “Admin panel and usage metering”
Variable Purpose Required Default
USD_EUR_RATE conversion rate for the usage dashboard required 0.92
METERING_TOKEN secret. Service token for the monthly retrieval of the usage aggregates by an operator. Empty means the endpoint is switched off optional empty, line commented out

Freeze the rate in USD_EUR_RATE per billing month instead of updating it live. Otherwise the percentage display fluctuates without anyone having consumed more. The panel freezes the rate of a completed month anyway, a later change does not alter past months.

The transitional panel is the official AGPL panel of LibreChat. It only starts with the explicit interim profile and is not part of the product. Details are on the licenses and origin page.

Multiple instances

Section titled “Multiple instances”

These three names are unique across all of Docker. If only one instance runs on the machine, they stay commented out. If several customer stacks are to run on the same machine, they have to differ per stack, otherwise the second stack does not start.

Variable Purpose Required Default
STACK_NAME prefix of all containers of this stack optional eucowork, line commented out
DOCKER_SUBNET own bridge subnet, free of collisions with other stacks and with VPN routes optional 172.28.0.0/16, line commented out
SANDBOX_NETWORK own network towards the code interpreter optional eucowork-sandbox, line commented out

In addition, PORT, ADMIN_SIDECAR_PORT and OFFICE_ADDIN_PORT have to differ per stack.

Never share the sandbox network

SANDBOX_NETWORK is the only place where code from users runs on the machine. Every customer gets a separate network. Also never shared: database, uploads, the .env and the inference key.

More on this on the multiple instances page.

Variables you should not change

Section titled “Variables you should not change”

Two values are deliberately set the way they are in the template. Both look harmless, and both break something when they are changed.

DISABLE_COMPRESSION=true

Section titled “DISABLE_COMPRESSION=true”

LibreChat writes its responses as server sent events, but never calls res.flush() while doing so. The compression in Express therefore buffers the entire stream until the end of the response. A response header was measured after 26 seconds instead of after 0.3 seconds.

For the browser this is barely noticeable. For clients with an idle timeout it aborts every longer response. This affects the Outlook add-in in particular, whose webview aborts after around 60 seconds even though the response is still completing on the server. The typical symptom: the add-in reports a loading error.

There is no downside, because Caddy still compresses for browsers and correctly leaves text/event-stream alone.

BAN_VIOLATIONS=true

Section titled “BAN_VIOLATIONS=true”

Without this flag LibreChat does not check blocks at all. The Sperren (block) function in the admin panel does create an entry, but nobody is locked out. Anyone who considers the block function credible and sets the value to false has a button with no effect.

Related to this: NON_BROWSER_VIOLATION_SCORE=0. The anti abuse heuristic of LibreChat rates requests without a browser typical user agent so highly that it blocks the user and the IP address immediately. In a stack with sidecars and API access this leads to lockouts. The rate limiting of sign-in attempts stays active regardless.
